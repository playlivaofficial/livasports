Neon autosuspend assessment — PROPOSED, NOT ENABLED
Official docs say new connections wake suspended compute; cold buffers can add
query latency, and session-scoped state is lost. This application uses durable
leases and transaction-scoped advisory locks, not a session-held scheduler.
Repository operations close pools; auth uses its existing pool. Public session
reads retain DB-backed security rate limiting; no security gate is removed to
force idle periods. Frequent queries may prevent suspension altogether.
The current 10s connection timeout / 5s repository statement timeout and actual
authenticated cold-wake behavior need a controlled acceptance before any change.
Changing autosuspend or sizing is reliability-sensitive and requires explicit
authorization. Do not simulate cloud wakeup by stopping Production or create a
paid test branch. Savings require measured idle intervals, not 24h minus CPU time.
